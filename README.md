# 이음(IEUM): 국가유산 AI 해설 서비스

> 국가유산과 나를 잇다  
> 공식 자료 기반 RAG와 사용자 맥락 기반 해설을 통해 국가유산 관람 경험을 하나의 이야기로 이어주는 AI 해설 서비스입니다.

## 1. 프로젝트 개요

**이음(IEUM)**은 사용자의 언어, 이용 상황, 관심 카테고리에 따라 국가유산 해설을 다르게 제공하는 AI 기반 국가유산 해설·추천 서비스입니다.

기존 국가유산 정보는 안내판, 리플릿, 오디오 가이드, 전시안내 앱, 공공 포털 등을 통해 이미 제공되고 있습니다.  
하지만 대부분 고정된 설명을 전달하는 방식이기 때문에, 사용자가 지금 현장에 있는지, 다른 장소에서 탐색 중인지, 어떤 관점으로 이해하고 싶은지에 따라 해설 흐름을 바꾸기는 어렵습니다.

이음은 공식·공공 데이터를 기반으로 RAG 검색을 수행하고, 사용자의 맥락을 Context Prompt에 반영하여 개인화된 멀티모달 해설 경험을 제공합니다. 해설 이후에는 관심 카테고리와 관련된 다음 유산 및 콘텐츠 추천으로 탐색을 이어갑니다.

## 2. 선택 주제

SSAFY X Kakao Tech Bootcamp AI Hackathon  
정부 선정 「AI 민생 10대 프로젝트」 중 **④ 국가유산 AI 해설사** 주제를 기반으로 기획했습니다.

## 3. 핵심 문제 정의

문화유산 정보는 이미 존재합니다.  
부족한 것은 사용자의 상황과 관심사에 맞춰 **무엇을 먼저 보고, 어떤 관점으로 이해하고, 다음에 무엇을 탐색할지 이어주는 해설 흐름**입니다.

### 세부 문제

| 문제 | 설명 |
| --- | --- |
| 해설 경로 부족 | 방문 이후 무엇을 먼저 보고 어떤 순서로 이해할지 안내받기 어려움 |
| 고정형 해설 | 사용자의 관심사, 언어, 이해 수준, 이용 상황에 따라 설명 관점이 달라지기 어려움 |
| AI 신뢰성 문제 | 생성형 AI가 공식 근거 없이 역사 정보를 생성할 경우 오류와 환각 위험 존재 |
| 경험 단절 | 하나의 유산 설명 이후 다음 유산, 다음 주제, 관련 콘텐츠로 이어지는 흐름 부족 |

## 4. 서비스 핵심 흐름

```txt
언어 선택
→ 현장 방문 / 비현장 탐색 선택
→ 위치 기반 유산 선택 또는 검색
→ 관심 카테고리 선택
→ 공식 자료 기반 RAG 해설 생성
→ 텍스트 + TTS + 공식 이미지 제공
→ 다음 유산 추천
→ 관심 기반 K-콘텐츠 추천
→ 탐방 기록 및 리워드 확장
```

## 5. 주요 기능

### MVP 범위

| 기능 | 설명 |
| --- | --- |
| 언어 선택 | 한국어, 영어, 일본어, 중국어 등 해설 언어 선택 |
| 현장 / 비현장 선택 | 현재 장소 기반 탐방과 다른 장소에서의 탐색 흐름 분기 |
| 유산 선택 | 위치 기반 목록 또는 검색으로 해설 대상 선택 |
| 관심 카테고리 선택 | 역사, 건축, 예술·상징, 왕실문화, 종교·제례, 과학·기술 등 선택 |
| RAG 기반 해설 | 공식 자료를 검색한 뒤 LLM이 사용자 맥락에 맞게 재구성 |
| TTS 음성 해설 | 현장에서 화면을 오래 보지 않아도 들을 수 있는 해설 제공 |
| 공식 이미지 제공 | 공식 이미지와 출처를 우선 사용하여 이해 보조 |
| 다음 유산 추천 | 카테고리, 키워드, 시대, 장소 기반으로 관련 유산 추천 |
| 기본 K-콘텐츠 추천 | 사용자가 추천 흐름을 종료하면 관심 주제 관련 콘텐츠 추천 |

### 확장 기능

| 기능 | 설명 |
| --- | --- |
| AI 참고 시각화 | 공식 이미지가 없거나 소실·훼손되어 이해가 어려운 경우 참고용 이미지 생성 |
| Graph DB 기반 추천 | 유산-시대-인물-양식-키워드 관계를 활용한 추천 고도화 |
| 행동 로그 기반 프로파일링 | 사용자의 선택 기록을 반영한 개인화 추천 |
| Multi-Persona 해설 | 왕, 장인, 백성 등 다양한 관점의 몰입형 해설 |
| 리워드 / 랭킹 | 방문 기록, 해설 청취, 즐겨찾기 기반 지속 사용 유도 |
| K-콘텐츠 추천 고도화 | 사용자 기록과 콘텐츠 메타데이터를 함께 반영한 추천 |

## 6. AI 기술 구조

이음의 AI는 단순히 문장을 생성하는 챗봇이 아닙니다.  
공식 자료를 먼저 검색하고, 검색된 근거를 사용자의 언어·이용 상황·관심 카테고리에 맞게 재구성합니다.

```txt
사용자 Context 수집
→ Metadata Filtering
→ Hybrid Retrieval(Vector + BM25)
→ RAG Context 구성
→ Context-Aware Prompting
→ LLM 해설 생성
→ 출처 기반 응답 반환
→ TTS 변환
→ 다음 유산 / 콘텐츠 추천
```

### 핵심 기술

| 기술 | 역할 |
| --- | --- |
| RAG | 공식 자료를 먼저 검색하여 신뢰성 있는 해설 근거 확보 |
| Vector DB | 의미적으로 가까운 설명 문서 검색 |
| BM25 | 국가유산명, 인물명, 시대명 등 정확 키워드 검색 |
| Metadata Filtering | 언어, 지역, 카테고리, 출처 기준으로 검색 범위 제한 |
| Context Prompt | 사용자 상황과 관심사를 프롬프트에 반영 |
| LLM | 검색된 공식 근거를 읽기 쉬운 해설로 재구성 |
| TTS | 텍스트 해설을 오디오 가이드 형태로 변환 |
| Recommendation | 다음 유산과 관련 콘텐츠 추천 |

## 7. 데이터 활용 방향

이음은 단일 API에 의존하지 않고, 유산 ID를 중심으로 기본 정보, 설명 문서, 이미지, 좌표, 카테고리, 추천 관계를 연결하는 통합 데이터 구조를 지향합니다.

| 데이터 소스 | 활용 역할 |
| --- | --- |
| 국가유산검색 API | 국가유산 기본 정보, 주소, 좌표, 설명, 대표 이미지 |
| 궁궐·종묘 Open API | 현장 데모용 핵심 해설과 이미지 |
| 국가유산 지식이음 | 보존과학, 전통재료, 연구 자료 기반 심화 해설 |
| TourAPI | 역사관광지, 주변 장소, 탐방 흐름 추천 |
| 이뮤지엄 API | 관련 유물·소장품 이미지와 설명 연결 |
| 향토문화전자대전 | 지역 설화, 인물, 사건, 생활문화 스토리 확장 |
| 문화재 공간정보 API | 고도화 단계에서 문화재 경계·도형 좌표 활용 |
