# 02. AI 기술 문서

## 1. AI 활용 목표

이음의 AI는 단순히 문장을 생성하는 챗봇이 아니라, 공식 데이터를 검색하고 사용자의 맥락에 맞게 해설을 재구성하는 역할을 합니다.

핵심 목표는 다음과 같습니다.

1. 공식 자료 기반 RAG로 역사 오류와 환각을 줄입니다.
2. 사용자의 언어, 이용 상황, 관심 카테고리에 맞춘 해설을 생성합니다.
3. 텍스트, TTS, 공식 이미지를 결합해 현장 사용성을 높입니다.
4. 해설 이후 관련 유산과 콘텐츠 추천으로 경험을 이어갑니다.
5. 출처 표시와 Fallback 응답으로 AI 해설의 신뢰성을 확보합니다.

## 2. 전체 AI 처리 흐름

```txt
사용자 입력 수집
→ 언어 / 현장·비현장 / 유산 / 관심 카테고리 Context 구성
→ Metadata Filtering
→ Hybrid Retrieval(Vector + BM25)
→ RAG Context 구성
→ Context-Aware Prompting
→ LLM 해설 생성
→ 출처 기반 응답 반환
→ TTS 변환
→ 다음 유산 / K-콘텐츠 추천
```

## 3. 공식 자료 기반 RAG

### 도입 이유

국가유산 해설은 역사 정보의 정확성과 신뢰성이 중요합니다.  
일반 LLM만 사용하면 실제 역사와 다른 내용을 그럴듯하게 생성할 수 있습니다.

따라서 이음은 LLM이 사전 학습 지식만으로 답하지 않도록, 공식·공공 데이터에서 관련 근거를 먼저 검색한 뒤 그 근거를 바탕으로 해설을 생성합니다.

### 핵심 원칙

```txt
역사 팩트 = 공식 자료에서 검색된 문서
표현 방식 = LLM이 사용자 관심사와 언어에 맞게 재구성
```

### RAG 파이프라인

```txt
공식 데이터 수집
→ HTML / JSON / CSV 정제
→ 문서 단위 정리
→ Chunk 분할
→ Metadata 부여
→ Embedding 생성
→ Vector DB 저장
→ BM25 인덱스 구성
→ 사용자 Context 기반 검색
→ LLM 해설 생성
→ 출처 포함 응답 반환
```

## 4. 검색 전략

### 4-1. Metadata Filtering

카테고리, 언어, 지역, 출처, 유산 ID 등의 메타데이터를 먼저 사용해 검색 범위를 좁힙니다.

### 4-2. Vector Search

문장을 의미 단위로 임베딩하여 비슷한 의미의 문서를 찾습니다.

### 4-3. BM25 Keyword Search

국가유산 데이터에는 고유명사와 전문 용어가 많습니다.  
따라서 명칭, 시대명, 인물명, 건축 용어를 정확히 찾기 위해 키워드 검색을 함께 사용합니다.

### 4-4. Hybrid Retrieval

Vector Search와 BM25를 결합해 의미 검색과 정확 키워드 검색의 장점을 함께 사용합니다.

| 검색 방식 | 역할 |
| --- | --- |
| Vector Search | 의미적으로 가까운 문서 검색 |
| BM25 | 고유명사와 전문 용어 정확 검색 |
| Metadata Filtering | 검색 범위 사전 제한 |
| RRF | 여러 검색 결과 순위 결합 |

## 5. Context-Aware Prompting

같은 국가유산이라도 사용자의 언어, 이용 장소, 관심 카테고리에 따라 다른 해설을 생성해야 합니다.

### 일반 Prompt

```txt
경복궁을 설명해 주세요.
```

### Context-Aware Prompt

```txt
사용자는 한국어를 사용하고, 현재 경복궁 현장에 있으며,
건축 카테고리에 관심이 있다.
공식 자료를 근거로 근정전의 건축적 특징을 쉽게 설명하라.
출처에 없는 내용은 추측하지 말고, 어려운 용어는 짧게 풀어 설명하라.
```

## 6. 카테고리별 해설 라우팅

| 카테고리 | 프롬프트 방향 |
| --- | --- |
| 역사 | 시대 흐름, 사건, 변화 과정 중심 |
| 건축 | 배치, 구조, 공법, 관찰 포인트 중심 |
| 예술·상징 | 문양, 색채, 장식, 상징 의미 중심 |
| 왕실문화 | 의례, 왕실 생활, 궁중 문화 중심 |
| 종교·제례 | 불교, 유교, 제례, 신앙적 의미 중심 |
| 세계유산 | 탁월한 보편적 가치와 국제적 의미 중심 |
| 과학·기술 | 천문, 음향, 제작 기술, 보존과학 중심 |
| 생활문화 | 의식주, 지역 생활, 민속, 일상 문화 중심 |

## 7. LLM 해설 생성 방식

LLM은 역사 지식을 단독으로 만들어내는 역할이 아니라, 검색된 공식 자료를 사용자 맥락에 맞게 재구성하는 역할입니다.

### 입력

- 사용자 언어
- 이용 상황
- 선택 유산
- 관심 카테고리
- 검색된 공식 자료
- 출처 정보
- 해설 난이도

### 처리

- Context Prompt 적용
- 카테고리별 설명 재구성
- 쉬운 용어 설명
- 추천 이유 생성
- 선택 언어에 맞춘 해설 생성

### 출력

- 사용자가 읽기 쉬운 텍스트 해설
- TTS에 적합한 문장
- 다음 행동으로 이어지는 추천 문구
- 출처 정보

## 8. TTS 기반 음성 해설

국가유산 현장에서는 사용자가 화면을 오래 보기 어렵습니다.  
따라서 해설을 텍스트뿐만 아니라 TTS 음성으로 제공해 오디오 가이드처럼 들을 수 있는 경험을 만듭니다.

## 9. 이미지 제공과 AI 참고 시각화

### MVP

MVP에서는 공식 이미지가 있는 경우 공식 이미지와 출처를 우선 제공합니다.

### 확장

현재 직접 볼 수 없거나 훼손·소실되어 이해가 어려운 유산의 경우, 확장 기능으로 AI 참고 시각화를 제공합니다.

중요 안내 문구:

```txt
AI가 생성한 참고 이미지입니다.
실제 복원 결과가 아닌 이해를 돕기 위한 시각화입니다.
```

## 10. 추천 로직

MVP에서는 복잡한 개인화 모델보다 카테고리, 키워드, 시대, 지역 기반의 규칙 추천 또는 간단한 유사도 추천을 우선 적용합니다.

확장 단계에서는 Graph DB 기반 관계 추천, 사용자 행동 로그 기반 프로파일링, K-콘텐츠 메타데이터 기반 추천 고도화를 적용합니다.

## 11. 오류 방지 전략

| 레이어 | 설명 |
| --- | --- |
| 공식 데이터 소스 우선 | 임의 웹 자료가 아니라 공식·공공 데이터 우선 사용 |
| Chunk 단위 출처 추적 | 모든 문서 Chunk에 원본 문서명과 URL 연결 |
| 근거 기반 생성 | 검색된 근거 안에서만 해설 생성 |
| Fallback 응답 | 근거가 부족하면 억지로 답하지 않고 안내 |
| 검증 로직 | 생성 답변이 검색 근거와 충돌하지 않는지 점검 |

## 12. MVP AI 범위

### 포함

- 공식 자료 기반 RAG 해설
- 관심 카테고리별 프롬프트 라우팅
- 선택 언어 기반 해설 생성
- 출처 표시
- TTS 재생
- 공식 이미지 제공
- 간단한 관련 유산 / K-콘텐츠 추천

### 확장

- AI 참고 시각화
- Graph DB 기반 추천
- 사용자 로그 기반 추천 개선
- Multi-Persona 해설
- 관리자용 RAG 품질 모니터링
